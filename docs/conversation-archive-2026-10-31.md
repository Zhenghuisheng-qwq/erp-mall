## 最终业务约定

### 权益包与公共商品

- 权益包维护参与组合的产品类型，商品模型负责结构与合法规格，两者不混为一套配置。
- 使用流程：明确选择设备 → 按权益包类型范围及正式兼容性查询获取真实可售 SKU → 添加商品 → 填数量与报价 → 保存草稿或确认清单。
- 选择设备只作为选配上下文，购买手机需明确点击加入；MAT 不能作为销售 SKU。
- 公共商品池保存已有 SPU 的引用，不复制商品。启用的公共商品在自由组合及权益包模式均自动展示供选择，不要求每次手动加入引用。
- 没有销售 SKU 的公共 SPU 可以展示空状态，但不能把物料当成可购买规格。
- 草稿允许未报价，确认需补齐报价；明确填写 0 表示免费，不能与未报价混淆。
- 新设备入口不能被上次缓存设备覆盖；切换设备重新核对候选，有效商品保留数量和报价。维护后返回应保留有效未保存输入。
- 已确认清单保持历史快照，不能因当前商品或适用关系修改而重写。

### 兼容性

- 最终界面：适用关系列表 → 新增或编辑 → 选商品 SKU → 勾选设备型号 → 保存。
- 支持按产品类型和关键词找商品，型号支持搜索和多选。使用稳定身份关联，不按名称推断适用性。
- 批量默认“新增适用型号”，保留各 SKU 原有关系；“替换适用型号”需要明确选择，移除时确认，只影响本次选择的 SKU。
- 取消关联表示删除普通适用依据，不自动改成明确不适用。
- 普通页面不再要求填写共同依据、核验状态、条件表达式，也不展示复杂预览审核流程。
- 保留底层统一查询、既有通用/条件声明、明确不适用及冲突保护；简单编辑不能覆盖明确否定，也不删除高级历史资料。
- 保存沿用 RBAC、受控命令、并发与存储协调；失败保留输入，关闭/离开/刷新保护未保存内容，身份切换清理编辑状态。
- 权益包沿用同一份正式查询，不新增第二套兼容算法。

### 二手机

- 手工建档不依赖模型树、分类、产品类型、PLN 或 MAT。每台实物生成独立 UsedSku；品牌与型号规范化后能唯一匹配时复用 UsedSpu。
- 同规格的不同实物仍有独立编号、价格与身份；有歧义时明确选择已有主体或新建，不静默合并。
- 名称必填；分组、售价、成本、序列号、IMEI、图片、备注、扩展字段可选。不强制固定成色档位。
- 复制只带通用商品信息，不复制 IMEI/序列号、价格、检测备注及原状态。
- 状态为待上架、在售、已售、归档；已售和归档只读，不能直接重上架或删除。普通删除仅允许没有流转历史的待上架实物。
- SPU 汇总实际关联实物、在售数量及在售价格区间；未报价和 0 元区别处理。
- 与全新商品数据隔离；本轮不接入订单、支付、权益包，也不提供二手保存视图或批量导入覆盖单机历史。

## 当前入口与实现定位

- `/benefits/manage`：权益包管理。
- `/benefits/shopping`：权益包选购及自由组合。
- `/benefits/public-pool`：公共 SPU 商品池，支持商品列表及原分类/产品类型树筛选。
- `/compatibility`：简化后的兼容性列表及单个编辑窗口。
- `/spus?goods=used`、`/skus?goods=used`：二手 SPU/SKU；原列表顶部可切换全新/二手，筛选随模式切换。

主要实现：

- `src/domain/usedGoods/index.ts`：二手实体、身份、价格、状态及数据保护。
- `src/components/used-goods/`：手工建档、列表、模式切换和动态字段筛选。
- `src/views/ProductWorkspaceView.vue`：现有 SPU/SKU 路由的模式容器。
- `src/views/CompatibilityView.vue`：简化兼容性页面。
- `src/domain/compatibilityWorkspace.ts`：普通关联新增/替换的安全批量变更，复用原有保存与查询能力。
- `src/stores/catalog.ts`、`catalogAccess.ts`、`src/domain/rbac.ts`：受控保存及权限接入。
