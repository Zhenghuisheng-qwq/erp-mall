# 商品配置工作台 V2 演示版

## R01：节点业务配置与路径限制

在模型设计器选中值节点，点击「业务配置」。公共目录跨分类/类型复用；销售定位、物料策略支持仅当前值或当前值及下级；允许值限制支持上级值约束真实下级目标属性。配置不是规格轴。命名入口沿用原命名编辑器。

冲突可保存草稿，但受影响的发布和新建执行会被拒绝，不自动覆盖或求交集。面板可查看已发布配置快照。物料策略目前仅配置、解析和展示，尚未实现多路径共用 MAT 建档。

本轮修复 ProductPlan 创建 SKU 遗漏 COMMON 来源节点的问题。实现、逐项验收和边界见 [R01 验收报告](docs/r01-node-business-configuration.md)。领域检查：`npm run check:r01`；独立 Chrome 闭环：`npm run check:r01:browser`（用 `R01_BROWSER_OUTPUT` 指定独立输出目录）。

独立前端。数据只存在打开它的浏览器里，不连接客户数据库。

## 启动

在项目目录执行：

```bash
npm install
npm run dev
```

终端会打印访问地址。

构建静态文件：

```bash
npm run build
```

构建结果在 `dist`。把这个目录交给任意静态站点服务即可部署，不依赖本机盘符或固定端口。

本地预览构建结果：

```bash
npm run preview
```

## 演示说明

- 数据在浏览器 localStorage，键名 `iyge-v2-mock-db`，当前版本号 15；兼容读取旧版本，不清空历史数据。
- 演示版支持普通 HTTP，各浏览器按站点独立保存本地数据，无需 HTTPS 或 Web Locks。有 Web Locks 时自动使用跨标签页锁；没有时使用本页保存队列，不保证同时跨标签页写入的原子性。实际存储失败仍提示。
- 顶栏可以重置全部、重置当前模块、导出和导入。
- 预设商品都标了「预设演示」，不是线上导出。
- 左侧菜单默认展示全部功能。右上角可切换「管理员 / 运营」。
- 没有真实密码。账号页只校验密码表单，不保存。

## SKU 视图工作台

SKU 管理提供本机视图工作台：筛选先应用、再保存，支持条件组、动态字段、列宽/冻结、多级排序、分组及收藏。操作和验收说明见 [SKU 视图工作台](docs/sku-views-workbench.md)。

## 还没接真实后端的部分

分类映射、参数角色、必填、商品族、批量保存事务、规则状态，都在浏览器里计算。

对象怎么连、配置怎么从词表走到规格再走回总览，写在 [docs/商品配置闭环.md](docs/商品配置闭环.md)。

## SPU / SKU 管理

从「商品管理」进入独立的 SPU 管理和 SKU 管理。先保存 SPU，再手工创建或从模板、模型、规划分批追加 SKU；物料继续使用独立的「物料建档」入口。

本轮数据兼容、页面职责、旧链接和验证证据见 [docs/spu-sku-management.md](docs/spu-sku-management.md)。

```bash
npm run typecheck
npm run check:frontend
npm run check:spu-sku
npm run check:integration
npm run build
```

浏览器检查使用独立上下文和项目的 playwright-core，需要已安装 Chrome；可用 `BROWSER_CHANNEL=msedge` 选择 Edge。不会读取或清空日常浏览器数据。

## 导航与商品筛选

顶部按钮统一展开/收起导航；左下“导航设置”保留单栏/双栏偏好。SPU/SKU 列表通过“商品分类”和“更多筛选”即时筛选；“列表设置”集中管理常驻分类栏、列、排序、分组和保存视图。

本轮迁移规则、检查与截图见 [导航与筛选验收报告](docs/frontend-navigation-filter-ux.md)。`npm run check:navigation-filter` 使用独立浏览器上下文及开工源码快照；可用 `NAV_FILTER_BASELINE` 指定基线目录，缺失时会明确失败。

## 历史验收：V2 模型选择器

商品模型设计器允许属性下面再挂属性。新增商品选择器必须按当前节点路径展开，不要把同级属性自动提升到当前页。

品牌下面同时有 Apple（属性值）和型号（属性）时，品牌下拉是「Apple、型号」。选 Apple 就进入 Apple 的子节点；选型号才进入型号节点。不要品牌一行、型号一行同时出现。

这条按现在的 mock 数据验收。以后改成接口数据时再另说，现在不要为接接口去改选择器。锁定范围和完整规则见 [docs/商品配置闭环.md](docs/商品配置闭环.md) 第 5 节。

## 权益包：产品类型组合

权益包继续保存跨分类产品类型集合。商城选设备后可直接自由选配，也可采用已有包；公共池自动展示，共享同一适用判断，配套商品前置筛选，添加与确认复核。数量、报价、草稿、切换取消和确认历史保护保留。



公共商品池：商品中心的权益包分组提供独立菜单“公共商品池”（/benefits/public-pool），进入页面后从商品库添加 SPU；添加界面复用分类／产品类型树筛选与 SPU 勾选列表。维护全局集合 publicSpuPool；按包选购和自由组合自动展示全部启用公共 SPU，无需逐包绑定或本次手动添加，点规格旁的 ＋ 才加入清单。无销售规格或未上架时显示原因。commonSpuIds 保留旧记录兼容及实际加购来源，不作为公共候选的必选清单。已有记录不迁移补字段。类型集合支持主机分类内类型及跨分类配件类型，公共 SPU 可跨分类。候选动态展开真实 SKU，按 SKU ID 去重并保留销售状态检查；配套商品按分类范围展示；确认快照冻结公共来源。公共池新增、启停、移除分别使用既有权益包新增、编辑、删除权限与 SPU 查看权限，销售用户只有使用权限，不自动扩大角色授权。

专项检查：npm run check:public-spu（领域检查使用真实 Store 持久化与严格 RBAC，浏览器使用隔离数据，不修改用户商品）。

二手商品：在 SPU／SKU 工作台顶部切换“全新商品 / 二手商品”。二手资料直接手工建档，独立保存在 usedGoods 中，不进入商品模型、PLN、MAT、标准 SKU、兼容性或权益包。相同品牌与型号仅在标准化精确命中唯一 SPU 时自动归属，每台实物独立编号。分组、价格、设备标识及补充信息均可选；已售和归档记录保留，只读且不可再次销售。二手页提供关键词、品牌、型号、分组、状态和价格范围筛选，不使用全新商品的保存视图。

## 分类用途与跨分类权益包

商品模型配置 → 分类用途配置，可逐项设置主机或配件（包含增值业务）。新增分类时选择用途；子分类独立配置。旧分类未配置时沿用产品类型用途，不自动迁移商品。配置用途会统一当前分类下类型的有效用途，混合分类请先整理。权益包选择主机归属分类，可跨分类选择配件类型，继续沿用分类范围校验、报价与冻结快照流程。

分类用途支持独立增删改查（可新增维修等用途），用途名称与主机/配件/其他业务规则分开。已关联分类的用途禁止删除或直接改变业务规则，可改名；解除绑定后可删除。用途页支持直接新增分类、选择上级，分类编辑页也可绑定/清除用途，分类树同步显示用途标签。旧 host/accessory 分类字段兼容读取，不自动改写商品或历史清单。检查：`node scripts/run-domain-check.mjs scripts/category-purposes-check.ts --strict` 与 `node scripts/browser-category-roles.mjs`。

## 权益包分类选购范围

权益包管理现维护“主机分类 → 配件分类”的两级关联，不改变原商品分类树。一级仅主机用途，二级仅配件用途；双方分类的启用产品类型动态形成边界，选购在此范围内自由组合商品。公共池、加购和保存均遵循同一边界，仅展示范围内真实在售 SKU。新版首次加载会按本次需求移除旧权益包配置，保留商品与销售历史；已有苹果/华为样例目录整理为手机、保护及保护设备、电源与线缆，提供手机配件选购范围，商品展示名不含“演示”。自定义目录请明确配置用途与关联。

验证：`node scripts/run-domain-check.mjs scripts/benefit-category-range-check.ts`；`node scripts/browser-benefit-category-ranges.mjs`。

手机主机目录新增“新机 / 二手机”子分类；现有苹果、华为标准商品归新机。手机范围包含其主机子分类下的产品类型，选购页可筛选新机/二手机。二手机分类先留空，不接入 UsedSku 建档、状态或销售流程。已有二手工作台数据保留隔离。

权益包选购支持“只选主机 / 主机＋配件”，普通购买商品继续受选购范围限制。选购页可从商品库单独添加赠品，赠品不限普通范围（可送另一台主机），配件按分类范围展示；仅可选择真实在售 SKU，不接入二手实物。赠品显式标记、单价固定 0，需随正常选购商品一起保存，确认快照保留赠品身份。赠品不能与普通商品以同一 SKU 重复加入，切换设备按最新资料复核。验证：`node scripts/run-domain-check.mjs scripts/benefit-gifts-check.ts`、`node scripts/browser-benefit-gifts.mjs`。

## 二手机逐步回收

在商品资料管理 → 手机 / 二手机 → 商品模型中维护“二手机回收模型”。该模型是一条只有 ATTRIBUTE、没有 VALUE 的属性链，默认品牌 → 型号 → 颜色 → 内存 → 容量；可用现有模型编辑器继续调整。回收页 `/used-intake` 直接读取该模型的当前属性顺序，逐步填值后建立独立待上架 UsedSku。多模型可在回收页选择；模型调整后旧输入需要重新核对，已回收资料保持快照。独立“手机回收配置”页已停用，旧地址跳转商品模型列表。

检查：`node scripts/run-domain-check.mjs scripts/used-intake-check.ts`、`node scripts/browser-used-intake.mjs`。

二手 SPU/SKU 列表从二手机模型和既有回收快照读取动态字段；SKU 显示单机值，SPU 汇总关联设备的不同取值。筛选使用品牌、型号、各模型字段的实际取值、状态与价格范围；多个字段需同时匹配同一台单机。二手机的纯属性链允许不预设 VALUE 并发布为资料模型，保留结构与属性引用校验，不生成规格组合、规划编号或物料；全新商品维持原取值校验。检查：`node scripts/run-domain-check.mjs scripts/used-model-list-check.ts` 和 `node scripts/browser-used-model-lists.mjs`。

回收填写交互：当前字段有非空内容后自动显示下一字段，不再点击下一步；各属性框提示“没有该属性请填‘无’”，最后统一点击“保存”。填“无”的属性照常显示在二手 SPU/SKU 列表；品牌或型号为“无”时不自动把不同实物归到同一主体。纯 key 规则根据模型所属的二手机分类（包括下级）判断，任意模型名称和编号均适用。

选购顺序为“当前主机 → 对应权益包与购买商品 → 页面底部选择赠品”。赠品支持下拉搜索主机、“只送主机 / 主机＋配件”，所勾主机与配件全部为0元，配件按赠送主机对应的分类范围筛选。无额外主机正常购买入口，新保存也拒绝额外购买组合。赠品绑定本次主机与权益包，切换主机/包时复核并确认移除不再符合的赠品；已确认历史记录保留。检查：`node scripts/run-domain-check.mjs scripts/extra-bundles-check.ts`、`node scripts/browser-benefit-gifts.mjs`。

兼容性模块已移除：删除页面、导航入口、维护命令、匹配查询、条件/否定/通用声明逻辑及专用测试。商品用途与主机身份投影分别由 productTypePurpose、catalogDevices 提供，权益包和赠品只按分类范围与在售状态选购。既有兼容性原始字段和确认快照原样保留为历史数据，不再参与计算。验证：`node scripts/run-domain-check.mjs scripts/compatibility-removal-check.ts`、`node scripts/browser-benefit-gifts.mjs`。

## 配件 SPU 反向关联主机 SPU

兼容性配置 `/compatibility/config` 选择配件 SPU、单选或多选主机 SPU；列表 `/compatibility/list` 按整款商品查询、编辑和解除关系，颜色、容量等 SKU 不重复展示。关联保存稳定 SPU ID，未建立销售规格的普通 SPU 也可配置；物料档案不参与。旧 SKU 关联首次加载时按实际 familyId 合并到 SPU 并去重，原始记录保留。引用不完整的旧记录会在列表提示核对，不按名称猜测。SPU/SKU 详情均可进入对应配件 SPU 的配置。授权码沿用原关联权限，失败/并发/未保存保护保留；已关联 SPU 删除前需解除关系，单个 SKU 不再因这类关系锁定删除。本轮仍只维护关联资料，不改权益包范围候选。

验证：`node scripts/run-domain-check.mjs scripts/spu-host-links-check.ts --strict`、`node scripts/browser-spu-host-links.mjs`。
